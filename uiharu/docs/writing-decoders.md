# Writing a decoder

How a protocol is added to `crates/uiharu-protocols`: its contract, its decoder, its synthesizer, its tests and its page. A decoder is written either in the DSL — a TypeScript module under `dsl/decoders/`, compiled to Rust by the tool chain of [dsl.md](dsl.md); PWM, SPI, SPI NOR and UART are; while it is under work, `uiharu decode --ir dsl/ir/<name>.json` runs its IR interpreted, on the engine's other decoders, without generating its Rust (dsl.md §8) — or by hand in Rust, in the same shape, which is what this page describes. The I²C module (`src/i2c/`, whose contract is `dsl/contracts/i2c.ts`) and the 24xx EEPROM decoder (`src/eeprom24xx/`) are the reference for every rule here; [design.md](design.md) explains the runtime they run on. A hand-written decoder built on a generated contract (the SD card decoder on `spi.events`) reads it through `uiharu_core::dsl::FramedBus`, as `src/sdcard_spi/` does.

## Sources and implementation boundary

uiharu is Apache-2.0. Cite the protocol's public specification, vendor datasheet or application note for wire behavior and expected values. sigrok and DSView implementations may be consulted for behavior, edge cases and feature comparison; record those reference sources and distinguish consultation from copied or adapted code. GPL code must not be copied into Apache-2.0 files or introduced as a dependency. If actual source adaptation requires a licensing decision, record that blocker and continue other work.

For the decoder expansion through P4, write new decoders in TypeScript using the existing DSL and contracts wherever possible. If a protocol needs an IR, code-generation, interpreter or runtime extension, record its required behavior, a minimal desired TS example, the exact missing capability, expected events/recovery and other affected protocols, then skip it. Do not extend the backend during this expansion or add a handwritten Rust replacement to bypass the limitation. New contract declarations and ordinary generated IR/Rust output are allowed when supported by the current toolchain. USB request/control-transfer/descriptor layers are deferred.

## Where things go

```text
crates/uiharu-protocols/src/<name>/mod.rs       re-exports
crates/uiharu-protocols/src/<name>/events.rs    the contract: event types, ids, schema id — or dsl/contracts/<name>.ts, declared
                                                in the DSL and generated into crates/uiharu-dsl-protocols
crates/uiharu-protocols/src/<name>/decoder.rs   the node: config, validation, props, the async run loop
crates/uiharu-protocols/src/<name>/bus.rs       the cursor consumers read a framed contract through (one declared in the DSL is
                                                read through FramedBus instead)
crates/uiharu-protocols/src/<name>/synth.rs     a waveform builder for tests and tools
crates/uiharu-protocols/tests/<name>.rs         integration tests on synthesized waveforms
docs/protocols/<name>.md                        the contract and the decoding rules, for users of the stream
```

A decoder built on another contract (SPI NOR on `spi.events`, an EEPROM on `i2c.events`) is a single file or module named after the protocol, with its own events and tests. Add the module to `src/lib.rs`; touch nothing else outside your module (not `uiharu-cli`, not `design.md`, no new dependencies — `serde`, `thiserror`, `proptest` and `uiharu_core::testing` are what there is).

For a built-in DSL decoder, re-export its generated module from `uiharu-protocols`
and register the generated node, configuration and event type in `uiharu-registry`.
Declare both application locales in the TS module. Export its catalog metadata
with `cargo run -p uiharu-registry --example export_decoder_manifests -- <name>`
after running `pnpm dsl:generate`; format and include the resulting
`manifests/<name>.json`. Registry tests compare every registered DSL decoder with
its loaded IR, including ports, events, configuration, defaults and localized copy.
The generated and interpreted paths must also pass the same independent protocol
vectors and streaming-invariance tests.

Generated IR and Rust are ignored, disposable local output. Run `pnpm dsl:generate` before direct workspace Cargo commands, CLI tools, interpreted decoding or metadata export. `pnpm test` and `pnpm test:watch` prepare only IR; `pnpm bindings` generates Rust too. Commit the TypeScript sources and keep the handwritten production `src/lib.rs` wrapper and independent `uiharu-ir/tests/fixtures/pwm.json` tracked. See [the DSL workflow](dsl.md) for setup, output paths and checks.

## The contract

The contract is the event stream between layers — what a decoder emits and what decoders built on it read. Design it for the bus, not for the protocols above it. It is written in Rust (`src/<name>/events.rs`, as `src/microwire/` does) or declared in the DSL — a module under `uiharu/dsl/contracts/` with the event type, its enums and the `eventSchema` call (`contracts/i2c.ts` is the model, [dsl.md](dsl.md) §2.3 describes the declaration), compiled and generated with `pnpm dsl:generate`, its types re-exported from the decoder's module as `src/i2c/mod.rs` does — which is what a decoder written in the DSL needs in order to read it. The rules below describe what the contract says, whichever way it is written.

- Every kind of event has a role, declared with the contract (`.roles({…})` in the DSL) or, for a contract written in Rust, in the node type's manifest (`crates/uiharu-registry/manifests/<type>.json`: `"role"` beside the kind's `"fields"`, with `"errorWhen"` for the field values that make an event an error). [dsl.md](dsl.md) §2.3 lists the roles. Pick the one a reader of the bus would give the event, whatever its name: SPI NOR's `begin` carries the opcode and is a `command`, a USB transaction's `begin` carries the token and is an `address`. Mark as errors only the values the specification defines as wrong — a parity bit, a CRC, an address nobody acknowledged — and never a value a normal exchange can have.

- One schema per contract, `SchemaId::new("<name>.events", 1)`, implemented by the payload enum through `EventSchema`. A change that breaks readers is a new version.
- The payload is an enum with `#[serde(tag = "kind", rename_all = "kebab-case")]` on the enum and `#[serde(rename_all = "camelCase")]` on its fields (so `period_ticks` is written `periodTicks`, as port properties are; `kind` itself cannot be a field name), fields named as the standard names them, numbers as the narrowest integer that fits (a field that may reach 2^53, such as a 64-bit identifier, is marked `#[serde(with = "uiharu_core::hex_u64")]` so that JSON carries it as a hexadecimal string), `Option` for a line that is not connected or a value that could not be seen — never a made-up zero. Events carry bus data only, no interpretation and no UI text: what a byte means is the next layer's business.
- Where the bus frames its traffic (chip select, start/stop, a frame's SOF/EOF), the contract frames too: a `begin` carrying an id, the frame's events carrying that id, an `end` carrying the id and the reason — the normal one and the abnormal ones (`aborted` for a gap or the end of the samples). A frame already under way when the samples begin or resume after a gap begins with `partial: true`. Give the reasons the names a reader of the bus would use.
- The output declares in `Props` what readers may require: `wordBits`, `bitOrder`, which lines are present, the mode, the framing — camelCase keys, values a reader can require to equal one value or one of several, or to lie at or above, at or below, or within bounds (`Requires::equals`, `one_of`, `at_least`, `at_most`, `within`).
- A framed contract comes with a cursor consumers read it through: `uiharu_core::dsl::FramedBus`, which a contract declared in the DSL gets from its framing declaration (`i2c::I2cBus` is `FramedBus<I2cEvent>`), or a hand-written cursor in the same shape for the older contracts (`microwire::MicrowireBus`): `next()` waits for the next frame, gap, progress or end; the frame cursor offers the frame's primitives only — the next word with every line's value, the next word or the normal end, draining — and `consumed()` for the provenance of what was read. The cursor is made with the output's progress sink (`I2cBus::new(io.input(0), out.progress_sink())`) and passes the progress it meets inside a frame on through it, held back to what was consumed since the decoder last took the provenance; a writer that takes provenance early and keeps it for an event still to come — a batch being filled — tells the sink what it holds (`sink.hold(Some(start))`, `None` once the event is out), or the promise check in the tests fails. A stream that can be unframed (SPI without chip select) is read through the same cursor: `next()` opens the unframed transaction at its first word and it ends at a gap or the end of the stream, so draining it is never the right move. Byte order, field widths, integer assembly and which line a protocol reads are the consuming decoder's own code: a contract is the more useful the less it knows about the protocols above it.

## The decoder

A decoder is a `Node`: a configuration struct with `Default`, `validate()` and `props()`; a `spec()` declaring one input (`InputSpec::new::<Arc<LogicBlock>>("logic", Requires::new().at_least("channels", highest + 1))` for a bus decoder, `InputSpec::new::<LowerEvent>("bus", requires)` for a stacked one) and one output (`OutputSpec::new::<Event>("events", props)`); typed port helpers (`Spi::input(node)`, `Spi::events(node)`); and `start`, which binds the ports and returns `Box::pin(run(…))`.

`run` is an `async fn` over the runtime's handles and follows these rules:

- A decoder that reads several inputs waits until all of them have an item (`uiharu_core::ready_all`) and takes the one whose `Item::time` is earliest, the lowest port on a tie; one that reads the samples beside a stream seeks the cursor at every event and every progress item, so that the blocks behind are let go (design.md §4). Both keep the events the same whatever the blocks and queues; a lookback the source cannot hold makes `Pipeline::push` report a stall.
- Every read and write is an `await`: `SignalCursor::next_change(mask)`, `next_change_before(mask, until)` and `sample()`, `Inbox::recv`, a cursor's `word()`, `Outbox::emit/gap/progress/end`. Nothing is consumed by an operation that did not complete, so a decoder paused on output never reads its input again or sends an event twice; do not cache items to work around backpressure.
- Timed protocols (UART, CAN, 1-Wire, USB …) convert bit times to ticks with `io.time_base()` in integer arithmetic (state the rounding in the module documentation), `seek(tick)` to a sample point and `sample()` there, and wait for an edge within a bit with `next_change_before(mask, until)`, which returns `Change::Quiet` at the deadline. A frame that ends after a silence ends when the silence is _known_ to have passed — by the next frame's first edge or byte, by a `Progress` tick, or by the end of the samples — and its end event is placed at the computed tick, never at the moment it was noticed, so that the result does not depend on the blocks. `io.input_props(index)` gives a stacked decoder what the bus below declared (its word width, its lines), so that it does not ask for it twice.
- State is what the protocol needs to continue — the frame under way, the bits of the current word, a bounded batch — and nothing more. Never hold a whole frame or transaction; every buffer has a declared bound (a `const`), and a batch goes out when it is full or when the frame ends.
- Behaviour must not depend on how the samples are cut into blocks, on where the reader pauses, or on queue sizes and budgets. The signal cursor carries the levels before its position across blocks; only the first sample of the stream and the first after a gap are never edges — use `sample()` there to learn the bus state, and begin a frame as `partial` when the bus is found busy.
- A gap or the end of the samples while a frame is under way ends it with the abnormal reason, then the gap or end is passed on; leftover bits never make a word; events of other channels changing at the very tick a framing line changes belong to no frame (state the rule in the module documentation, as `spi/decoder.rs` does). Progress is passed on, held back to the start of whatever is under way (`min(t, in-flight start)`), since it promises that nothing starting earlier follows (design.md §2); a decoder built on time acts on the tick a progress item carries, never on its arrival.
- Every event states its provenance: `Provenance::one(tick)` for an event decided at one sample, `Provenance::over(span, settled)` for one covering several — the span of the bits or words it is made of, `settled` the tick at which it became certain, so that the stream's events settle in order (a batch flushed by a frame's end settles at that end). Decoders on a contract take the provenance of what they consumed from the cursor (`tx.consumed()`) and pass it to the writer.
- A decoder built on a contract has a body for one frame and a recovery around it, as `eeprom24xx/decoder.rs` does: the body reads through the cursor and returns early on the cursor's error; the recovery closes what the body opened with the reason the error names (`Incomplete` for a frame that ended normally but too soon, `Aborted` for a cut-off frame, a gap or the end of input) and the main loop passes gaps, progress and the end down. Only the read that is allowed to see the normal end returns it; a frame the body did not finish is drained for it.
- Module documentation states the decoding rules as a bullet list, cites the specification, and names the limits (word widths, modes, what is out of scope).

## The synthesizer

`synth.rs` builds `LogicBlock`s of the bus for tests, the CLI's generator and benchmarks, in the shape of `spi::synth::SpiWaveform` (the synthesizers stay hand-written, for generated decoders too): constructed from the decoder's config, the channel count, the samples per bit (or half period) and a start tick; methods for idle time, for framing and for one word or symbol honouring the config (mode, bit order, polarity); `position()` and `finish()`. Generators of higher protocols (`nor_read_words`) build word lists for the bus synthesizer rather than samples.

## Tests

- Unit tests in the modules for configuration validation, `props()`, and the serialized shape of each event kind (`serde_json`), as `spi/events.rs` does.
- Integration tests in `tests/<name>.rs` on synthesized waveforms through `uiharu_core::testing::Harness`: build it with a closure that adds and connects your node(s) and returns the output to read; `run_all` for one piece, `feed`/`feed_cut` for blocks of chosen sizes with gaps and pauses, `end()` to finish; `items`, `events()`, `tap()` for a second stream. Check exact events, spans and settled ticks for a representative frame in every mode or option the decoder has; the partial frame at the start; the frame cut off by the end of the samples; the gap inside a frame and the resynchronization after it; leftover bits; the line that is not connected; a value that shows up before its frame ends (incremental decoding).
- Call `uiharu_core::testing::assert_block_invariant` on at least one rich waveform with gaps: it runs the samples through every block size, reading pattern and queue configuration and demands the events of one uninterrupted run, and checks every run against the promise of progress (`assert_progress_promise`, which a test of its own can also call on a harness's items). A proptest over random traffic, as `tests/acceptance.rs` does for SPI → SPI NOR, is welcome where the protocol has many shapes.
- For a stacked decoder, test the requirements: a lower stream that does not satisfy them must be refused with `GraphError::Requirement` naming the property.
- Tests use `expect("…")`, never `unwrap()`; `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --all --check` and `cargo test -p uiharu-protocols` must pass.

## The page

`docs/protocols/<name>.md` is for users of the stream: the contract (each event kind, its fields and what they mean on the bus), the props the output declares, the requirements a stacked decoder has, the decoding rules (framing, sampling, what is marked `partial`/`aborted`, what is dropped), the configuration (lines, modes, options) and the limits. English, concise, tables for the events; no comparison with other tools.

## Commits

Fine-grained Conventional Commits with the `uiharu` scope, subjects imperative and in lower case, ≤ 72 characters, bodies saying why: `feat(uiharu): decode i2c transfers from logic samples` (contract, decoder, synthesizer and their tests in one commit, or the contract first when it stands alone), `test(uiharu): …` for tests added on their own, `docs(uiharu): …` for the page. lefthook formats and lints what is committed; never `--no-verify`.
