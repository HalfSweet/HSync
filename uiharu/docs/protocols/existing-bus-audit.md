# Existing P3 bus capability audit

Audit date: 2026-10-22. This completes the P3 comparison of the existing bus
profiles and records the subsequent TypeScript semantic consumers. It does not
claim complete DSView annotation parity. Modbus, SMBus, PS/2 and debug work is tracked in
[debug-bus-porting-coverage.md](debug-bus-porting-coverage.md).

The reference revisions are DSView
`2e9e2c8e726df4ef5687d39b83d4f797cc44b574` and upstream libsigrokdecode
`71f451443029322d57376214c330b518efd84f88`. The comparison reads the decoder's
declared options and its implementation, then checks HSync's contract, config,
protocol documentation and tests. An upstream TODO is not counted as a working
capability. Reference text rendering, raw bit annotations and typed semantic
events are separate capabilities.

## Evidence and verification

The existing native protocol tests are `can.rs`, `lin.rs`, `dmx512.rs`, `midi.rs`,
`mdio.rs`, `microwire.rs`, `eeprom93xx.rs`, `uart.rs`, `onewire.rs`, `usb.rs` and
`usb_pd.rs` in `crates/uiharu-protocols/tests/`, with scheduling/block invariance
cases in the acceptance suite. The supported profiles and source specifications
are documented in the same-named pages (USB PD uses `usb-pd.md`). This audit
does not substitute for the final workspace regression run, nor for the new
decoder tests recorded in the other family ledgers.

The continuation's `uiharu-interp/tests/p3_semantics.rs` covers the LIN, DMX and
MIDI consumers with generated/interpreted comparisons and scheduling/gap cases;
`uiharu-interp/tests/p4_devices.rs` covers CFP over the native MDIO contract.
`tests/mdio.rs` includes independently assembled rising/falling-edge vectors.
These source/suite references describe evidence scope; final integrated counts
are reported by the task coordinator. Exact native/DSL type ownership preserves
wire schemas while some Rust convenience methods now require the documented
extension traits. Historical contract probes in other ledgers must be read as
historical evidence, not current blockers.
