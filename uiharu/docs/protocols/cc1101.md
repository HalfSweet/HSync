# CC1101 SPI

`cc1101` consumes eight-bit MSB-first SPI with chip select, MOSI and MISO.
Its TypeScript source is `dsl/decoders/cc1101.ts`, independently implemented from
[TI SWRS061I §§10.2–10.6, Tables 42–45](https://www.ti.com/lit/gpn/cc1101).
There are no decoder-specific options.

Every captured register byte retains raw address/value/direction and adds a
`register` event with the manufacturer's identifier. The catalogue covers all
47 configuration registers `00`–`2E`, all 14 status registers `30`–`3D`, PATABLE
and FIFO. Reserved/unmapped addresses are explicitly unknown or unsupported;
configuration bursts crossing the published range terminate as unsupported
before inventing status-register accesses. FIFO/PATABLE bursts retain their
selected address instead of being mislabeled as consecutive registers.

All 13 documented command strobes are named, including SFSTXON, SXOFF, SWOR and
SWORRST. Strobes accept either R/W bit value when B=0. For addresses 30–3D,
B=1 selects a read-only single status-register access: it does not enable an
incrementing burst. Attempted status writes and reserved strobe 37 report
unsupported. The header's raw status byte remains visible.

Packet format, CRC/whitening, modulation, synchronization/preamble, RSSI/LQI,
CRC indication, MARC state and FIFO byte/error fields retain their existing
interpretation. These are observed register fields; a strobe is a request, not
proof that a radio changed state or sent an RF packet. This node does not compute
frequency/rate equations from an assumed crystal, reconstruct over-air packets
or infer unseen register settings.

State is bounded to scalar counters and the current SPI transaction. Partial
transactions are drained; missing data, gaps and end-of-capture terminate with
incomplete/aborted events and do not invent bytes. The first out-of-range burst
byte remains raw data and the rest is drained with an unsupported end.

`tests/radio_registers.rs` uses independent manufacturer-table vectors for the
complete config range, status/address discrimination, strobe variants,
FIFO/PATABLE and gap/backpressure recovery. It compares full generated and
interpreted events/provenance. Existing SPI profile tests also cover named
operation and packet/status subfields. The [SPI ledger](spi-porting-coverage.md)
records broader profile limits.
