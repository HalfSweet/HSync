# MLX90614

`mlx90614` is a TypeScript DSL decoder over `i2c.events`, implemented independently
from the [manufacturer datasheet](https://media.melexis.com/-/media/files/documents/datasheets/mlx90614-datasheet-melexis.pdf) (Rev 20, §§4.1.4.3.6–4.1.4.3.8 and figures 6–7). Its source is
[`mlx90614.ts`](../../dsl/decoders/mlx90614.ts); generated Rust and IR are never edited by hand.

## Configuration and contract

`address` is a seven-bit target address, default `0x5a`. Ten-bit addresses and
other targets are ignored. Input is `i2c.events` version 1; output is
`mlx90614.events` version 1 with output property `address`.

| Kind      | Meaning                                                                                 |
| --------- | --------------------------------------------------------------------------------------- |
| `begin`   | One addressed segment: `op`, lower `tx`, `read` direction, address `ack`                |
| `pointer` | Attempted register/command pointer and its ACK; absent on pointerless devices           |
| `byte`    | Immediate raw byte, optional known `register`, `read`, `ack`                            |
| `field`   | Decoded numeric field: `register`, enum `field`, magnitude `value`, `negative`, `valid` |
| `end`     | Segment result: complete, incomplete, aborted or nack                                   |

A read-ending NACK is normal and its final byte is retained. An unacknowledged
write does not change interpreted device state and invalidates the pointer.
An unknown pointer stays unknown; raw bytes are retained. START/repeated START
closes a segment; a STOP closes the last segment. Initial partial I²C frames are
drained. Gaps and truncation abort open segments and clear pointer knowledge.

## Device rules

The command is one byte, followed by either write data or a repeated-START read in the same I²C transaction. Words are LSB then MSB then PEC; raw words are emitted when both bytes arrive, and `pec` validates the later packet checksum (CRC-8 polynomial 0x07, initial zero, over address bytes, command and data, excluding ACK/START/STOP). `expected-pec` exposes the calculated byte. Read command 6 is ambient, 7 object 1 and 8 object 2. Temperatures use 0.02 K units; signed centi°C is represented by magnitude `value` and `negative`. Bit 15 is the temperature error flag and makes the derived field invalid. A missing PEC marks the operation incomplete. The primary published vector is `b4 07 b5 d2 3a 30`: word 0x3ad2, PEC 0x30.

## Streaming and limits

Every byte is reported before later data is read. There is no transaction-sized
buffer: state is a pointer, counters, constant-size mode flags, and at most one
unfinished byte with its provenance. Multi-byte field spans cover only their
observed bytes and settle on their final byte; a held first byte holds progress
back to its start. Byte/field events preserve consumed I²C event provenance;
segment ends use the item that decided them. Bounded queues and awaited reads/writes
provide backpressure and cancellation.

Read flags without repeated START, sleep, PWM, EEPROM erase/write timing and raw-IR sign/magnitude interpretation are not implemented. Raw RAM/EEPROM words and ordinary SMBus write-word PEC are preserved; an orphan read lacks a command and has no decoded fields.
