# SPI and related device profiles

This ledger records the implemented public-specification profile, rather than treating a node name as full family parity. The TypeScript in `dsl/decoders/` is authoritative. Generated IR is disposable local output; regenerate and commit affected Rust with the sources using [the DSL workflow](../dsl.md). Run `pnpm dsl:compile` before direct Cargo tests; `pnpm test` prepares IR automatically. Device and transport vectors are in `tests/dsl_spi_devices.rs`, `dsl_spi_logic.rs`, `dsl_sd_native.rs`, `dsl_sda2506.rs`, `dsl_tlc5620.rs`, `dsl_rgb_stream.rs` and `dsl_ade_stream.rs` under `uiharu-protocols`; radio register coverage also has `radio_registers.rs`. The vectors also compare generated and interpreted results, including exact event sequence/provenance, gaps and end. Queue topology can coalesce Progress differently, so both streams separately verify the progress promise. Broader workspace checks remain separate.

SPI overlays consume `spi.events` with MSB-first words. Most use observed chip select; RGB and ADE also accept explicitly aligned continuous byte streams without CS. Most use eight-bit words; AD5626, AD79x0, ADF435x, LTC242x and X2444 use one-bit words to represent the chip's non-byte frame widths. Both MOSI and MISO are required when a profile reads responses; ADNS5020 has an explicit shared-SDIO option. A gap aborts the current transfer. Complete fields emitted before an abort remain observations, not claims of a committed register or physical output. State is scalar and bounded; no whole transaction or framebuffer is retained.

The backend follow-up also completed the Winbond profile's observed-QE-gated
QPI entry/exit, complete-command B7/E9 address-width transitions, immediate
66/99 reset sequencing, dedicated four-byte commands and ID/security/extended
register layouts. Unknown QE state or a gap suspends unsafe command inference.
See [qspi-flash](qspi-flash.md) and [SPI NOR](spi-nor.md) for exact command scope.
This does not implement DSView Smart QSPI's heuristic per-byte lane selection.
SD follow-up adds all nonreserved CSD v1 fields, the five-byte CID product name,
R1/R6 status fields and R7 echo checks; SPI register decoding validates command
header bits and keeps internal CRC7/end checks separate from the data CRC16.

The TLC5620 implementation consumes logic directly; the earlier SPI-only scaffold was replaced. Missing LOAD requires an explicit aligned-start assertion. A gap never reapplies that assertion; parsing stays suspended without a new hardware boundary. Native SD R1 state changes require matching command indices, and fixed width remains fixed across CMD0. SCR fields follow SD Physical Layer Simplified v5.10 Table 5-17; new extended fields remain raw codes rather than inferred operating state.

Historical AM230x engineering-value overlay audit (resolved; see [am230x.md](am230x.md)): the native public `Reading.bytes: [u8; 5]` is retained unchanged. A virtual frontend probe replacing the DSL bounded byte vector with `readonly [u8,u8,u8,u8,u8]` fails at the bytes field: `the type readonly [u8,u8,u8,u8,u8] has no IR type; name a record or give an integer its width`. Current IR `Array { array, bound }` represents at most N elements, not exactly N, and generated Rust uses `Vec`. That would change both the public Rust API and deserialization acceptance, so the overlay is omitted. The minimal required capability is a fixed-length array IR type with generated `[T; N]`, interpreter validation and contract parity; no runtime algorithm change is needed. Native AM2302/DHT22 and DHT11 pulse/byte/checksum decoding remains available. Engineering conversions audited against the [Aosong AM2302 specification](https://www.aosong.com/uploadfiles/2025/04/20250417105409216.pdf): humidity in tenths of percent and sign-magnitude temperature in tenths of a degree; classic DHT11 decimal bytes require zero rather than inventing fractional values.

Existing APA102 audit: the native profile accepts eight-bit MSB-first mode 0/3 MOSI with optional CS/MISO. It decodes the 32-zero start, 111+five-bit brightness+BGR, SK9822 zero/reset handling, bounded pending bytes, gaps and provenance. Independent-model and scheduling tests cover the implementation. A 32-one end pattern remains ambiguous with white LED data without a configured chain length, explicitly documented in its existing profile. It remains separate from generic continuous RGB triplets; this is not an IR blocker.

Verified checkpoints include full ENC bank/dummy vectors; ADF4351 all-six-register, ADXL345 engineering conversion and all 17 RFM12 handlers; RGB/ADE CS-less and partial/gap tests; native/SPI SCR and TLC/SD audit regressions. Each compiled/interpreted comparison checks exact event sequence, sample provenance, gaps and end; progress may coalesce through an extra bridge queue, so both streams separately satisfy the progress promise.
