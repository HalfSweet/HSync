# PAN1321 SPP AT reference profile

Connect one UART direction per instance. Bytes stream immediately,
with CR/LF line framing, known JAAC/JPRO/JRES/JSDA/JSEC/JSLN command identifiers,
JAAC/JPRO mode values, OK/ROK status and numeric ERR codes. JSDA decimal payload
length controls binary data framing: CR/LF inside its declared payload is data.
No full line or payload is buffered. `max_bytes` bounds message length (default
4096, range 16–1048576). Framing/parity errors, breaks, gaps and EOF abort the
current line.

This is a limited reference profile: JSEC/JSLN parameters remain raw; no link,
security, initialization or request/response state is inferred. Unknown commands
remain raw lines with an unsupported end. Exceeding the length bound or encountering a corrupt UART frame discards input through the next CR/LF boundary. After a gap, the same boundary recovery prevents a trailing fragment from becoming a new command. The separate manufacturer's complete SPP-AT manual was not
available, so this does not claim every firmware command.

Source: [Panasonic PAN1321 SPP hardware data sheet](https://www.mouser.com/datasheet/2/315/panasonic_pan1321_datasheet-947359.pdf) establishes the UART/AT interface. Exact limited command facts are attributed to [libsigrokdecode PAN1321](https://github.com/sigrokproject/libsigrokdecode/tree/master/decoders/pan1321), Uwe Hermann (2012–2013, GPL). The TypeScript framing and field parser and test vectors are independently authored; no GPL implementation body is copied.

Input is the existing typed `uart.events@1` contract. Raw bytes are emitted immediately; all retained state has a fixed scalar bound, and emitted events use the bytes that establish their value as provenance. Unknown values are preserved rather than silently mapped to a known command.

Numeric field provenance covers the command prefix through the byte establishing the field. A single start provenance is held until message end; `max_bytes` bounds that progress hold, while every byte is emitted immediately.
